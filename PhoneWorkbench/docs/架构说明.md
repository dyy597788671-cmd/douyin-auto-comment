# 本地基础架构

代码版本：0.1.0。文档修订：1.2。当前已开发部分用于管理设备、目标账号、人工核验任务、内容记录和日志。影刀未接入，多账号养号流程暂停。

## 完整需求流程

以下保留用户原始流程，步骤是否保留与本轮是否开发分别说明：

1. 选择绑定的目标账号、关键词与内容类型。
2. 按原需求预设数量范围选择执行账号，使用对应手机上的抖音搜索关键词。
3. 筛选最新发布内容，图文按原需求选择对应内容类型；必要时下拉搜索结果。
4. 打开候选内容，再进入作者账号页核对目标身份。
5. 身份不符则返回搜索结果继续查找；身份相符则返回内容页。
6. 保留随机点赞、评论、转发动作节点。原需求为随机执行其中一至三个动作，操作时间在预设区间内随机，评论从预设回复池随机选择。该节点继续保留为项目功能需求，当前基础框架尚未实现。

第六步仍属于完整需求流程，不能因为尚未实现而删除，也不能把第五步核验完成当成整个流程已经完成。当前说明记录完整互动需求及其实现状态。本次澄清只修正文档，没有新增动作执行代码。

用户明确暂停的只是多账号养号流程，互动动作仍保留在项目需求中。当前已实现的人工核验任务是完整需求中的子流程，其“已完成”只表示人工核验完成，不表示随机互动节点已执行。尚未实现的动作不能报告为执行成功。

## 模块分工

界面通过本机 HTTP 接口访问业务层，业务层将数据保存到 SQLite。影刀适配层独立于界面与数据库，后续接入不得让界面直接驱动手机，也不得将“设备已登记”视为“设备已连接”。

| 模块 | 输入 | 输出与状态 |
|---|---|---|
| 设备管理 | 手机标识、备注、型号、当前登录账号 | 登记记录，连接状态默认待确认 |
| 目标账号库 | 昵称、抖音号、主页、参考头像、分组 | 待确认或人工已确认的身份记录 |
| 核验任务 | 一个设备、一个目标、关键词、内容类型 | 待核验、核验中、暂停、完成、失败、停止 |
| 内容记录 | 标题、链接、作者、时间、截图参考、核验结果 | 持久化核验记录，链接去重 |
| 日志 | 保存操作与任务状态事件 | 带时间的最近 500 条操作记录，完整历史保留在数据库 |
| 影刀适配层 | 将来核实的影刀连接能力 | 当前返回未配置，无执行能力 |

## 数据关系

每个任务关联一个设备和一个目标账号。每个内容记录关联一个目标账号，可以关联一个任务；关联任务与内容的目标必须一致。日志关联记录类型和编号。

数据库内部编号与抖音号、手机标识分别保存，不能混用。目标账号与手机当前登录账号分别登记；当前登录账号是手工资料，尚未自动读取或确认。

## 状态规则

| 当前状态 | 允许转入 |
|---|---|
| 待核验 | 核验中、停止 |
| 核验中 | 暂停、完成、失败、停止 |
| 暂停 | 核验中、停止 |
| 完成、失败、停止 | 终态；新任务需另建 |

同一个设备只能有一个核验中的任务。暂停释放本地任务占用；恢复时重新检查占用。此规则目前仅约束本工作台中的任务，尚不能检测外部影刀流程或其他工具对手机的控制。

重启时核验中的任务转为暂停，由用户确认后恢复。创建记录与日志、任务状态与日志均在同一数据库事务中保存。此版任务由人工推进，不包含后台调度器。

## 本地接口

| 方法和路径 | 用途 |
|---|---|
| GET /api/health | 服务与适配层状态 |
| GET /api/state | 当前管理数据与日志 |
| POST /api/devices | 登记设备 |
| POST /api/targets | 保存目标账号 |
| POST /api/tasks | 建立人工核验任务 |
| POST /api/contents | 保存核验记录 |
| POST /api/tasks/{id}/status | 推进任务状态 |

接口只监听 127.0.0.1。界面与服务同源，不开放跨域调用，不向外部网站发送数据。

## 影刀接入前置条件

需取得实际版本、套餐、手机自动化指令列表、设备连接方式、单台连接结果，再确定数据交换与连接读取方式。当前没有假设影刀存在某个 HTTP API、CLI 或 SDK，也没有生成可导入影刀的流程文件。

后续首次接入应先完成设备识别、当前登录账号读取、截图或公开内容读取等可独立验证的能力。保留返回证据与真实状态，失败时不能改写成成功。
